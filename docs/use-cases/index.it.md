# Casi d'uso

Percorsi concreti che mostrano come si usa Commandeck ogni giorno. Scegli quello più vicino alla tua situazione:

- **[Guida per principianti a Linux](beginner.md)** — nuovo di Commandeck (o di Linux)? Comincia da qui. Funziona per intero nella versione gratuita, senza SSH.
- **[Server multimediale Jellyfin](jellyfin.md)** — perché si blocca, che cosa riempie il disco, quale log leggere, riavviare e aggiornare, sia in Docker sia con installazione di sistema. *(Pro)*
- **[Batocera, la console retrogaming](batocera.md)** — perché un gioco non parte, un emulatore bloccato, uno schermo nero e un disco pieno, risolti dalla tua scrivania e senza tastiera sulla macchina. *(Pro)*
- **[Gestione di un server domestico](home-server.md)** — manutenzione con un clic per una macchina con Plex, Pi-hole o un NAS, via SSH. *(Pro)*
- **[Gestire un parco homelab](homelab.md)** — comanda più macchine da un'unica griglia, con pulsanti multi-macchina e profili di esecuzione. *(Pro)*
- **[Pilotare Commandeck da un'IA locale](local-ai.md)** — lascia che un'IA locale o nel cloud crei ed esegua i tuoi pulsanti tramite MCP. *(Pro)*
- **[Flusso di sviluppo](dev-workflow.md)** — la tavolozza di comandi di chi programma: compilare, testare, distribuire e leggere i log, in locale e su un server remoto. *(le parti remote sono Pro)*

!!! note
    Le guide con *(Pro)* si basano su macchine SSH, pulsanti multi-macchina, profili di esecuzione o IA/MCP: tutte funzioni di [Commandeck Pro](../pro.md). La versione gratuita copre l'uso locale (parti dalla guida per principianti).
